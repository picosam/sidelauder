# S15: which instance does a notification click activate?

Spike of spec §16.1, prepared 2026-09-29 on macOS 27.0 and **not run**.
Harness: `SpikeRunner s15` in
[`spikes/Sources/SpikeRunner/Hidden.swift`](../../spikes/Sources/SpikeRunner/Hidden.swift).

**Verdict: moved to M1a's daily use.** The trial needs ten real notification
clicks, each after a prompt in one of two hidden instances, about 15 minutes
of the operator's hands after an hour of other trials. The operator chose to
check it once in the built app instead. No design decision waits on it:
whichever instance a click activates, the rail follows the activation
(§9.10), and a wrong one is a documented limit, not a broken switch.

## What is ready

The harness ran end to end against its own windows standing in for the two
instances (smoke test, not a result). The operator marks each prompt with
⌃⌥⇧1 or ⌃⌥⇧2, and the harness hides that instance. After clicking a
notification, the operator declares whose it was with ⌃⌥⇧4 or ⌃⌥⇧5. The
harness takes the last Claude activation since the previous mark and scores
whether it was the declared instance. Other Claude copies are logged as
"other-claude", never by name. A repeat declaration with nothing activated
scores "none", and a mismatch scores as a failure.

## At M1a

In daily use with two or more profiles hidden, note which instance each
notification click brings forward, together with whether a Code session's
approval request posts a notification while hidden (S14). Either
answer is recorded against R16 and A19. If clicks land on the wrong
instance, the fallback stands as planned: document it, and point users who
rely on notifications at Stack.
